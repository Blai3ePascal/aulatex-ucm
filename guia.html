Primera instalación y uso

Fork creado por la Oficina de Software Libre y Tecnologías Abiertas

Esta entrega es completa. No necesitas instalar las versiones anteriores ni subir primero la v4. El editor, el gestor de bibliografía, el chat y las herramientas de publicación están incluidos. No se ha creado ni actualizado ningún repositorio de tu cuenta desde esta conversación.

1. Probarlo antes de publicar nada

Descomprime el ZIP completo en una carpeta. En Windows ejecuta ABRIR_EDITOR.bat, o abre PowerShell en esa carpeta y escribe:

python tools/vista_local.py

Necesitas Python 3.10 o posterior para esta vista local. Se abrirá http://127.0.0.1:8765/ en tu navegador; deja la terminal abierta. Si el puerto está ocupado, utiliza python tools/vista_local.py --port 8766. Ctrl+C detiene la vista. No abras repo-web/index.html haciendo doble clic: los módulos y el trabajador de Markdown necesitan HTTP(S).

La vista local sirve únicamente los archivos públicos del editor, en tu propio equipo. No expone el repositorio de documentos ni abre un servicio accesible por la red. Es una herramienta opcional para probar el paquete, no un servidor adicional exigido por la instalación en GitHub. En producción siguen utilizándose Pages, repositorios/API de GitHub y Actions.

Puedes cambiar el diseño, escribir Markdown y exportar archivos sin conectar una cuenta. El PDF LaTeX inicial es un ejemplo precompilado: no representa tus cambios. Para compilar LaTeX con la arquitectura incluida necesitas publicar el repositorio de documentos y conectar GitHub. Sin GitHub, guarda tu trabajo en ZIP antes de cerrar: la edición del ejemplo permanece en la pestaña, no en un disco sincronizado.

2. La nueva distribución

Archivos y herramientas de proyecto a la izquierda; código y lectura/PDF en el centro; conversación del equipo en un panel lateral cuando abres Chat. En pantallas estrechas, los paneles se apilan y el botón Archivos despliega la navegación.

El diseño utiliza bordes rectos, esquinas de 0–2 píxeles, separadores finos y controles con texto. No hay tarjetas flotantes, degradados decorativos ni burbujas de chat. El título y la lectura académica pueden usar serifas; el código sigue en una fuente monoespaciada del sistema. El paquete no incluye fuentes tipográficas.

El logo es el general UCM incluido en repo-web/assets/ucm-logo.png. No es el de la FDI, no se recolorea con los temas y no se descarga de otra web durante la edición. El crédito de la Oficina se conserva literalmente. La estética se inspira en la distribución de la captura proporcionada y en un entorno de trabajo sobrio; no incorpora código ni activos de Lichess.

3. Apariencia y accesibilidad

Pulsa Apariencia. La primera apertura utiliza UCM · claro, con el rojo #B71234, blanco y grises. Hay seis temas: UCM claro, UCM oscuro, Tablero claro, Tablero oscuro, Papel sepia y Alto contraste.

Puedes ajustar fondo, paneles, texto y acento; tamaño de interfaz entre 14 y 24 px; código entre 16 y 40 px; lectura entre 16 y 30 px; interlineado; anchura del lateral y reparto entre código y vista. La opción Controles amplios de 44 px facilita pulsarlos. Ajustar líneas largas elimina la capa de colores y el margen numerado para evitar desalineaciones con el texto envuelto.

El diálogo muestra la relación de contraste texto/panel. Los colores derivados de texto y enlaces se corrigen para no desaparecer sobre su fondo. Cambiar el tema solo cambia la interfaz: no modifica los colores de tus fuentes LaTeX, del PDF generado ni del logo.

Guardar apariencia la recuerda en este navegador; Cancelar o Escape restaura el aspecto anterior. Puedes exportar e importar un JSON de preferencias sin documentos ni credenciales. El botón Restablecer UCM claro recupera la base y después puedes guardarla.

Los controles tienen etiquetas, foco visible y navegación por teclado. El botón Más espacio oculta elementos secundarios. Los temas han pasado comprobaciones numéricas de pares de contraste y pruebas de distribución entre 390 y 1920 px. Esto no equivale a una auditoría completa WCAG, de lectores de pantalla o de cada combinación personalizada. La ampliación del navegador sigue disponible; prueba también tu magnificador y lector habituales.

4. Crear y escribir Markdown

Pulsa Nuevo proyecto, escribe un identificador y un título, y elige Markdown · cuaderno académico. Se crea documento.md como archivo principal y markdown como motor. Para explorar antes de crear, pulsa Probar Markdown.

Puedes tener .tex, .bib, imágenes y .md dentro de un mismo proyecto. La vista sigue el archivo abierto; el motor se asocia al principal. Al escoger un principal Markdown se configura el modo Markdown, y al escoger un .tex vuelves al motor LaTeX. El índice de la izquierda se construye con los encabezados del archivo Markdown.

La lectura se actualiza localmente mientras escribes, sin lanzar Actions. Admite encabezados, párrafos, enlaces HTTP(S)/correo, listas anidadas, tareas, tablas, citas en bloque, negrita, cursiva, tachado y bloques de código. Las imágenes admitidas son PNG, JPEG, GIF y WebP que ya estén dentro del proyecto y referenciadas por una ruta local. Las imágenes externas no se descargan automáticamente.

Descargar .md conserva el texto fuente. Exportar HTML crea una página autónoma, sin JavaScript ni token, con estilo de lectura e imágenes locales incorporadas. Imprimir / PDF utiliza la impresión de tu navegador: comprueba el resultado antes de distribuirlo. Guardar ZIP o guardar en GitHub incluye también tus archivos Markdown.

Qué no hace este modo

No convierte Markdown en un PDF mediante Pandoc/Actions. No resuelve fórmulas matemáticas, diagramas Mermaid, front matter editorial ni citas Pandoc [@clave] en la vista. El gestor bibliográfico puede insertar esa clave para un flujo posterior, pero no fabrica una bibliografía renderizada. Para composición tipográfica y referencias resueltas utiliza el modo LaTeX/XeLaTeX con Biber.

El HTML incrustado se muestra como texto: no ejecuta scripts, formularios, iframes ni SVG. La vista está limitada a 200 000 caracteres y el trabajador se detiene tras dos segundos de análisis; el archivo sigue disponible para editar o exportar. El renderizador incluido es un snapshot identificado de Marked 4.0.19, no la versión más reciente: consulta su licencia y las notas de mantenimiento en repo-web/vendor/. Las restricciones de salida y de tiempo son parte de esta implementación; no son una certificación general del parser.

5. Guardar y forzar guardado

Situación Guardar Forzar guardado
No has conectado GitHub Descarga un ZIP con el proyecto actual Descarga el ZIP inmediatamente; no simula una subida
GitHub conectado, cambios compatibles Combina y guarda una nueva revisión Lee la revisión más reciente y muestra qué se guardará
Cambios incompatibles entre autores Detiene el guardado y ofrece resolver Permite conservar tu versión de los archivos incompatibles después de confirmarlo
Solo tienes permiso de lectura No escribe No elude los permisos; está desactivado

En Forzar guardado, el diálogo identifica repositorio, proyecto, revisión y archivos afectados. Si tu versión va a sustituir cambios incompatibles, debes escribir GUARDAR. Puedes descargar tanto tu copia como la de GitHub; antes de aplicar una sustitución incompatible se inicia además la descarga de una copia ZIP de tu edición. Comprueba que tu navegador acepta esa descarga.

La operación crea un commit descendiente normal. No utiliza force-push ni borra el historial. La versión sustituida sigue recuperable en GitHub; los cambios compatibles y los archivos remotos independientes se conservan. No modifica proyectos ajenos ni workflows fuera de la carpeta seleccionada.

Si alguien guarda después de que hayas abierto la revisión de confirmación, se cancela la escritura y aparece un mensaje dentro del diálogo. Ciérralo y pulsa Forzar guardado otra vez para revisar la nueva situación. No se reintenta una sobrescritura automáticamente.

Atajos: Ctrl+S guarda o exporta; Ctrl+Shift+S abre el guardado forzado o exporta localmente; Ctrl+Enter, desde el editor, compila el principal o actualiza la vista Markdown. Los atajos no interceptan los diálogos abiertos ni el chat. El guardado automático de GitHub sigue siendo opcional y no compila por su cuenta.

6. Instalar desde cero en GitHub

Comprueba que tienes Python, Git y GitHub CLI (gh):

python --version
git --version
gh --version

Inicia sesión con tu usuario. Las credenciales no se pegan en archivos del paquete:

gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git
gh auth refresh -h github.com -s workflow

Desde la carpeta raíz del paquete, revisa primero el plan:

python tools/publicar.py --owner Blai3ePascal

Esta orden no crea nada. Después ejecuta:

python tools/publicar.py --owner Blai3ePascal --execute

Pide escribir CREAR. Publica repo-web/ como repositorio público aulatex-ucm y repo-proyectos/ como repositorio privado aulatex-proyectos. No sobrescribe nombres existentes. Comprueba en Actions el despliegue de Pages. Si falta activarlo manualmente: Settings → Pages → Source: GitHub Actions; después ejecuta el workflow de Pages.

La dirección prevista, solo una vez terminado correctamente ese despliegue, es https://Blai3ePascal.github.io/aulatex-ucm/. No está creada por descargar el ZIP.

Puedes sustituir el propietario por una organización donde tengas permisos y usar --web y --workspace para otros nombres. Para cada grupo con permisos distintos, crea otro repositorio de documentos, no una carpeta supuestamente privada dentro del mismo repositorio. La web puede reutilizarse.

7. Conectar, compartir y compilar

En Conectar GitHub, cada persona introduce su propio token. Para propietarios y miembros autorizados, configura un token fine-grained limitado al repositorio de documentos: Contents y Actions para guardar/compilar, Issues para chat y comentarios. La gestión de colaboradores necesita permisos administrativos adicionales; no los concedas a todo el grupo. El token se mantiene en memoria y se retira del campo tras comprobarlo.

Los colaboradores externos tienen limitaciones específicas en los tokens fine-grained. Consulta docs/INSTALACION-AVANZADA.md y la documentación oficial indicada allí antes de elegir el tipo de token o repartir accesos. No compartas tu token ni lo publiques en GitHub. Los roles reales de lectura y escritura corresponden a GitHub; un enlace de «lectura» no crea un permiso por sí solo. Una organización permite separar mejor esos roles; un repositorio compartido da acceso a todos sus proyectos e historial.

Chat se basa en Issues, no en un servidor de conversación ni en IA. Activa Issues y utiliza el permiso correspondiente. La actualización aproximada es cada 30 segundos mientras el panel es visible, más el botón Actualizar. Todos los participantes con acceso al repositorio pueden leerlo.

Bibliografía conserva la importación BibTeX/BibLaTeX, RIS y CSL JSON, el capturador de metadatos y las consultas mediante Actions. Importa, revisa y después incorpora las fichas. No es una sincronización completa con Zotero ni reconoce todas las webs.

La configuración LaTeX conserva XeLaTeX, pdfLaTeX, LuaLaTeX y Biber. Antes de usar documentos importantes, ejecuta en el repositorio privado Actualizar y verificar TeX Live y la comprobación en nube:

python tools/verificar_nube.py --owner Blai3ePascal --execute

La referencia heredada del compilador está fijada por digest y declara TeX Live 2026. No se presenta como la imagen más reciente ni como ejecutada aquí. Las compilaciones locales de pruebas utilizan la instalación indicada en sus informes. Pages no publica los documentos privados; los PDF permanecen en el repositorio de documentos y se recuperan con los permisos correspondientes.

8. Comprobación final en tu equipo

Prueba primero un proyecto vacío o el de bienvenida: cambia el tema; crea un Markdown, guarda ZIP, exporta HTML y vuelve a abrirlo; conecta un repositorio de prueba, guarda un .tex y compílalo; abre dos sesiones de cuentas distintas y comprueba el guardado normal y el forzado; verifica también una cuenta lectora y el chat. No migres aún material importante si alguna de esas comprobaciones falla.

Los informes locales están en docs/PRUEBAS.md y evidencias/v5/. Las pruebas de navegador usan una API GitHub simulada y un transporte de Worker simulado; la navegación HTTP de Chromium estaba bloqueada en el entorno de construcción. El servicio HTTP local sí se comprobó con un cliente Python. Quedan pendientes la autenticación/CORS real, la carga de módulos y Worker bajo CSP en tu navegador, invitaciones, despliegue Pages, APIs bibliográficas reales y la imagen Docker de Actions. No se ha realizado una auditoría integral de seguridad ni de accesibilidad.

Los editores con permiso de escritura del repositorio pueden modificar sus workflows por otras vías: no equivale a un servicio multiusuario resistente a colaboradores maliciosos. Usa repositorios separados, permisos mínimos y revisión del código. Actions sigue sujeto a las cuotas y políticas de tu cuenta.

Bibliografía: traer, revisar y citar

Tres entradas, una biblioteca editable

Bibliografía abre el gestor. El archivo .bib de tu proyecto sigue siendo la fuente de verdad: puedes editarlo fuera del gestor o exportarlo con el ZIP. No hay una base de datos opaca ni una cuenta adicional obligatoria.

Desde Zotero o una exportación de una web

Selecciona las referencias o la colección en Zotero, exporta a BibLaTeX, BibTeX, RIS o CSL JSON, y abre el archivo en el gestor. También puedes pegar esos datos en el cuadro y pulsar Revisar importación. No se conecta a tu cuenta Zotero, no sube tu biblioteca a un proveedor adicional y no importa automáticamente notas, adjuntos o PDF.

Revisa título, autores, año, revista/editorial, DOI y tipo. Cada ficha tiene Revisar / editar ficha: permite corregir el BibTeX que se añadirá. Selecciona las fichas y el archivo de destino —por defecto references.bib— y pulsa Añadir seleccionadas al proyecto. El cuadro de confirmación indica qué se añadirá, qué duplicados se omitirán y cuántas claves se renombrarán. Después guarda en GitHub.

El importador omite duplicados por DOI, o por coincidencia normalizada de título, autores y año. No detecta todas las equivalencias semánticas: dos versiones del mismo artículo o datos incompletos pueden requerir revisión. Una clave repetida para una referencia distinta se renombra con _2, _3, etc.; no se reemplaza silenciosamente la referencia existente.

Capturar una página que tienes abierta

El paquete contiene capturador/, una extensión Manifest V3 para carga local en Chrome/Edge. En el editor, Capturar una página abierta lleva a sus instrucciones y al ZIP de la extensión.

Abre chrome://extensions o edge://extensions, activa Modo de desarrollador, elige Cargar descomprimida y selecciona la carpeta que contiene manifest.json. Fija la extensión. En la página del artículo pulsa su icono y después Capturar esta página. Revisa lo encontrado y pulsa Copiar para AulaTeX o Guardar JSON. En AulaTeX, pega o abre ese JSON y revisa antes de añadirlo.

Solo se ejecuta al pulsar, con permisos activeTab, scripting y portapapeles. No tiene un token GitHub, un servicio de fondo ni permiso permanente para todas las webs. Lee el DOM de la página abierta, no las cookies. Si tu sesión da acceso a una página privada, el DOM puede incluir sus metadatos: revisa lo que vas a compartir.

Los detectores genéricos reconocen Highwire (citation_*), Dublin Core, JSON-LD y COinS. Una página puede describir varias referencias, además de recomendaciones: selecciona la correcta. Sin metadatos reconocibles se crea una ficha básica de título y URL con aviso, sin inventar autores.

No equivale al motor completo de Zotero. No se han incorporado sus traductores específicos ni se garantiza capturar todas las webs. No sortea muros de pago, no extrae el contenido de todos los visores PDF, no recorre iframes de otros dominios ni evade medidas anti-extracción. Zotero Connector y la exportación BibTeX/RIS siguen siendo una alternativa para los sitios que este capturador no reconoce. No está publicada ni firmada en las tiendas.

Por DOI, arXiv, PMID, ISBN o URL

Con el repositorio conectado, despliega Resolver DOI, arXiv, PMID, ISBN o URL con Actions. Escribe una consulta por línea, hasta 20:

10.1038/nphys1170
arxiv:1706.03762
pmid:31452104
isbn:9780306406157
https://www.ejemplo.org/pagina-de-la-publicacion

La última dirección es ilustrativa; sustitúyela por una página real. Al confirmar, la aplicación solicita importar-bibliografia.yml. El recuperador consulta Crossref/DataCite para DOI, arXiv, PubMed o Open Library, o lee metadatos HTML de una página pública. No ejecuta JavaScript de la web. Por eso las páginas que dependen de JavaScript pueden funcionar mejor con la extensión que con Actions.

Consultar resultado recupera las fichas para revisión, no las incorpora automáticamente. El identificador de solicitud permite volver más tarde. El resultado se conserva en la rama aulatex-imports, dentro del repositorio de documentos, nunca en Pages. Copia ese identificador antes de cerrar la pestaña; el estado de la solicitud no se guarda como una credencial local.

Las fuentes bibliográficas son sitios externos que se consultan, no infraestructura donde se aloja AulaTeX. El editor, los datos, el chat y las compilaciones siguen funcionando con GitHub. No se requiere Zotero Server, Firebase, una API de traducción alojada por nosotros ni un proxy de terceros.

El endpoint público puede cambiar, estar caído, responder 403/429 o no contener la ficha. No se prueba acceso a todas las editoriales. Se conserva un error por consulta y las referencias que sí se recuperan; revisa siempre la correspondencia entre la ficha y la publicación. Una ejecución interrumpida o agotada puede no publicar resultado: revisa Actions y vuelve a solicitar solo las consultas necesarias.

Citar y preparar el PDF

Busca una referencia por título, autor, clave o DOI. Con un .tex abierto, sitúa primero el cursor en el texto, abre el gestor y pulsa Citar. Se inserta \cite{clave} en el cursor. Copiar cita permite insertarla tú; Abrir .bib muestra su fuente.

Preparar bibliografía en el principal añade biblatex con Biber, \addbibresource{references.bib} y \printbibliography. Permite elegir numérico, autor-año, APA o IEEE para una configuración nueva. No cambia un estilo ya configurado. No convierte a la fuerza un documento basado en natbib, \bibliography o \bibliographystyle; esas plantillas se mantienen y deben configurarse según sus normas.

Guarda y compila con XeLaTeX, LuaLaTeX o pdfLaTeX. latexmk ejecuta Biber cuando el documento lo necesita. Importar referencias no demuestra que la revista acepte el estilo generado: revisa las instrucciones de publicación.

Límites técnicos y seguridad

Máximo 5 MiB y 2000 fichas por importación; la biblioteca muestra las primeras 200 coincidencias y permite filtrar. El parser admite llaves anidadas, comillas, escapes, números y macros @string ya definidas; no promete compatibilidad con todas las extensiones no estándar de BibTeX. Un @preamble se omite con aviso. Las claves de cita se restringen a caracteres seguros. El texto de metadatos JSON/RIS se escapa como LaTeX, y en la interfaz se representa como texto, no HTML.

Un archivo BibTeX escrito por un usuario puede contener TeX legítimo: no se elimina todo el TeX de ese formato. Compílalo solo en el contenedor restringido y con personas de confianza, igual que el resto de las fuentes. La ruta de destino se valida; no puede escapar del proyecto.

El recuperador limita tamaño, tiempo y redirecciones. Rechaza URLs con credenciales, puertos no estándar, parámetros con nombres de secretos y hosts locales/internos. Valida direcciones IP públicas y fija la IP comprobada al abrir el socket; vuelve a validar cada redirección. No utiliza cookies, credenciales de GitHub, proxies del entorno ni JavaScript remoto. Las pruebas de estos límites son simuladas; no constituyen una auditoría independiente del sistema.

Los identificadores/URL de una solicitud forman parte de una ejecución de Actions y de su resultado. No escribas datos privados ni enlaces firmados. En repositorios públicos, tanto las solicitudes como los resultados son públicos. Los resultados de importación no se borran automáticamente: el administrador debe planificar conservación, cuotas y copias de seguridad.

Chat y privacidad del equipo

Abre Chat después de conectar el repositorio. El panel permanece junto al editor y permite seguir escribiendo. Abrirlo solo consulta: la primera persona que envía un mensaje crea la conversación. Los mensajes se almacenan como comentarios de una Issue identificada por el proyecto; no se mantiene un servidor ni un job de Actions esperando mensajes.

Enviar mensaje o Ctrl+Enter publica el texto con la identidad real del token de GitHub. Responder incluye una mención y una cita breve del mensaje al que contestas. La casilla de contexto añade el archivo y el commit actuales, indicando si hay cambios locales sin guardar. No adjunta automáticamente el contenido completo de un documento.

Puedes editar o eliminar tus mensajes desde el panel, tras confirmación cuando se eliminan. No se ofrecen controles para modificar los mensajes de otra persona. GitHub conserva su propia autoridad y permisos: un administrador puede tener facultades adicionales desde GitHub. El código no suplanta autores ni atribuye el mensaje a una persona escogida libremente.

Actualizar consulta ahora; con el panel y la pestaña visibles consulta aproximadamente cada 30 segundos. La cola de la API, la red, una tarea en curso o un límite de peticiones pueden retrasarlo. No hay indicadores de escritura, voz, vídeo, cursores remotos ni entrega instantánea garantizada. Si la API rechaza una operación, aparece el error; no se anuncia un envío como correcto antes de guardarlo.

Se cargan los últimos 100–200 mensajes. Anteriores recupera páginas anteriores. Exportar cargados guarda únicamente los mensajes cargados en un TXT, no promete exportar todo un hilo largo sin recorrerlo. Un identificador de envío permite evitar el duplicado en reintentos inmediatos; no existe una transacción global de mensajería de exactamente una entrega. Una creación inicial simultánea puede dejar una Issue vacía adicional: se selecciona la conversación más antigua identificada, sin borrar automáticamente las otras.

Permisos y privacidad

Activa Settings → General → Features → Issues en el repositorio. Para escribir desde la aplicación: permiso de escritura del repositorio y permiso Issues: read and write en tu propio token. Un lector de AulaTeX puede consultar el chat pero la interfaz no le permite enviar. Las capacidades que GitHub pueda conceder por otras vías se rigen por GitHub, no por botones ocultos.

Todos los que accedan al repositorio podrán consultar sus Issues. No es un mensaje directo ni un canal privado entre dos miembros del mismo repositorio. En un repositorio público, la conversación es pública. La aplicación pide confirmación adicional antes de publicar en un repositorio público.

GitHub puede enviar notificaciones por los mensajes y menciones. Eliminar un mensaje no retira correos ni copias que alguien haya guardado. Configura las notificaciones en GitHub según las necesidades del grupo. No publiques secretos ni datos especialmente sensibles en este chat.

Los mensajes se muestran como texto: no se ejecuta HTML, no se cargan imágenes externas y las etiquetas potencialmente peligrosas se ven literalmente. Los tokens se mantienen en memoria y no se incorporan a mensajes, enlaces, archivos o exportaciones. No hace falta ningún token compartido para toda la clase.

El identificador del hilo está asociado al repositorio y la carpeta del proyecto. Renombrar/mover la carpeta no migra automáticamente la conversación anterior: su Issue permanece accesible en GitHub.

Qué se verifica del guardado forzado

La revisión no escribe por sí sola. Sin conflictos se crea un commit hijo; con archivos incompatibles se exige GUARDAR y se genera una copia ZIP local. Se comprueba la preferencia local autorizada, la conservación de un archivo creado remotamente, la permanencia de la revisión sustituida en la ascendencia y force:false en cada actualización de ref. Si cambia la cabeza entre revisar y confirmar, la API no recibe una publicación de la referencia. Un lector no puede forzar ni guardar desde la interfaz.

Las pruebas usan un repositorio simulado con blobs, árboles, commits y comprobación de fast-forward. Son pruebas del comportamiento de nuestro código; no son una invitación real ni una operación en tu cuenta.

Qué se verifica de Markdown y la interfaz

Los módulos reales se ejecutan en Chromium, con una adaptación de carga para el entorno. Se verifican la lectura, índice, listas/tareas/tablas, HTML inerte, enlaces peligrosos bloqueados, imágenes externas no cargadas, salida .md/HTML, ZIP local, proyecto Markdown guardado y reabierto por otro lector, cambios de tema, Cancelar/Escape, JSON de preferencias, ajuste de líneas, texto ampliado, controles de 44 px y distribución sin desbordamiento global entre 390 y 1920 px. Se han inspeccionado visualmente capturas claro/oscuro, personalización, móvil y guardado.

Los tokens de prueba no aparecen en el almacenamiento persistente simulado. Esto no demuestra que sea imposible un fallo de seguridad: no se ha hecho una auditoría completa ni un análisis de todas las extensiones de navegador que el usuario pueda tener instaladas.

Accesibilidad: alcance exacto

Las pruebas numéricas comprueban los pares principales de los seis temas, con objetivo de texto 4.5:1 y delimitadores activos 3:1. La aplicación deriva colores más legibles cuando los valores personalizados los harían desaparecer. El criterio de contraste procede de W3C: https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html.

No se declara conformidad completa WCAG. No se ha realizado una auditoría de lector de pantalla, magnificadores, zoom real del navegador al 400 %, teclado en todos los diálogos, orientación ni todas las combinaciones arbitrarias de preferencias. Las capturas a distintas anchuras prueban reflujo del DOM a esas anchuras, no equivalen a esas auditorías.

Limitaciones del entorno de pruebas

La política del entorno rechaza la navegación HTTP de Chromium con ERR_BLOCKED_BY_ADMINISTRATOR, incluso a 127.0.0.1. Por eso las pruebas de UI cargan el DOM mediante set_content, incorporan los módulos a un bundle de ensayo y retiran la CSP solo en el harness. La API de GitHub, las fuentes bibliográficas, storage, clipboard, parte de crypto y el transporte del Worker se simulan. El parser real se ejecuta para las pruebas funcionales; no se ha validado la carga nativa del Worker por URL bajo la CSP de producción.

No se ha comprobado autenticación real, CORS, tokens de colaboradores, invitaciones, cuotas, Pages, Actions en tu cuenta, capturas de todas las editoriales o la instalación completa del capturador. No se ha ejecutado la imagen Docker de producción.

Marked se distribuye como snapshot identificado 4.0.19, no como la versión más reciente. Consulta vendor/MARKED-NOTICE.md; su uso está restringido por los renderizadores de salida, el límite de entrada y el Worker con tiempo máximo. El administrador debe revisar y actualizar dependencias antes de abrir un servicio a terceros. No se ha incluido contenido remoto como código de terceros en tiempo de edición.
